# 🏗️ Architecture and Technical Design

## 1. Architecture summary
Fabulo currently follows a static-site architecture. The browser renders a single HTML page and retrieves local assets and CSS from the static host. The HTML also references the Tailwind browser CDN script.

There is no project-owned server, API, database, queue, authentication provider, or payment service.

## 2. Logical components

| Component | Responsibility | Source |
|---|---|---|
| Page composition | Content and page structure | index.html |
| Tailwind input | Directives and custom styles | input.css |
| Tailwind configuration | Content scanning and theme | tailwind.config.js |
| Build runner | npm scripts and dependency graph | package.json, lockfile |
| Local visuals | Editorial photos and vector assets | Images/ |
| Compiled CSS | Browser stylesheet | css/style.css generated by build |
| Browser | Layout, rendering, and interaction | Visitor browser |
| CDN dependency | Tailwind browser script | External URL in HTML |


## 5. Repository boundaries
- HTML is the page source of truth.
- Tailwind configuration controls utility generation.
- The lockfile controls reproducible npm dependency installation.
- Images are stored locally and referenced using exact relative paths.
- Generated CSS must exist in the published artifact.
- Documentation should not invent unimplemented backend components.

## 6. Production considerations

### CSS delivery
The current page references both generated CSS and a Tailwind browser CDN script. Decide on one deliberate production strategy. A local compiled stylesheet is generally more predictable, cacheable, and independent of runtime CSS compilation. Remove the CDN only after confirming the compiled stylesheet contains required utilities and testing the page.

### Asset delivery
Record source and license information, preserve filename case, use image dimensions, and optimize large assets. Consider lazy loading only for below-the-fold imagery.

### Hosting
A static host should publish the repository root after the build output is generated. Provider-specific settings must be documented only after the actual host is confirmed.

### Future dynamic services
If a backend or commerce capability is introduced, create a separate architecture decision and threat model. Define trust boundaries, API contracts, data ownership, authorization, validation, failure modes, and operational responsibilities.
